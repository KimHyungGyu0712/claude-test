## 1. 터미널 (PowerShell)

### 이게 뭔가
마우스로 폴더를 열고 더블클릭하는 대신, **글자로 컴퓨터에 명령을 내리는 창**이다.
Flutter 실행, Git 저장, 오류 확인이 전부 여기서 일어난다. AI가 코드를 써도 실행 버튼은 내가 여기서 누른다.

### 여는 법
- VS Code에서 `Ctrl + `` ` ``(숫자 1 왼쪽 키)를 누르면 아래에 터미널이 열린다. 이게 가장 편하다.
- 또는 시작 메뉴에서 "PowerShell"을 검색해서 연다.

### 꼭 알아야 할 명령 6개

| 명령 | 뜻 | 예시 |
|------|-----|------|
| `cd 폴더이름` | 그 폴더로 들어간다 | `cd app` |
| `cd ..` | 한 단계 위 폴더로 나온다 | |
| `ls` | 지금 폴더 안에 뭐가 있는지 본다 | |
| `cls` | 화면을 깨끗하게 지운다 (기록은 안 사라진다) | |
| `Ctrl + C` | 지금 돌아가는 프로그램을 멈춘다 | 앱 실행 중단 |
| `Tab` 키 | 이름을 반만 치고 누르면 자동 완성 | `cd 개` + Tab → `cd 개발...` |

### 출력 읽는 법
- 명령을 치면 글자가 쏟아진다. **마지막 몇 줄**을 먼저 본다. 결과와 오류는 대부분 끝에 있다.
- **빨간 글자**가 오류다. `Error`, `Exception`, `failed`라는 단어를 찾는다.
- 오류가 나면 **빨간 부분을 그대로 복사**해 둔다. AI에게 줄 때 필요하다.

### 직접 해보기
```

ls
flutter --version
```
- [ ] `ls` 결과에 `Agent.md`, `개발기획서.md`, `docs`, `app`이 보인다
- [ ] `flutter --version` 결과에 `Flutter 3.47`이 보인다

## 2. Git 5개 명령

### 이게 뭔가
Git은 **코드의 저장 지점(세이브 포인트)을 만드는 도구**다. 게임 세이브와 같다.
AI가 코드를 고치다가 망가뜨리면, 마지막 세이브 지점으로 되돌아간다. 그래서 **기능 하나가 잘 돌아갈 때마다 세이브(커밋)** 한다.

### 5개 명령

| 순서 | 명령 | 뜻 |
|------|------|-----|
| 1 | `git status` | 마지막 저장 이후 **무엇이 바뀌었는지** 본다. 빨간 파일 = 아직 저장 안 됨 |
| 2 | `git add .` | 바뀐 파일을 **전부 저장 대상에 올린다** (`.`은 "여기 전부") |
| 3 | `git commit -m "설명"` | **세이브**한다. 따옴표 안에 무엇을 했는지 한 줄로 적는다 |
| 4 | `git log --oneline` | 세이브 목록을 본다. 한 줄에 하나씩 |
| 5 | `git restore .` | 마지막 세이브 이후의 변경을 **전부 버리고 되돌린다** |

> ⚠️ `git restore .`는 저장하지 않은 작업을 지운다. 그래서 **AI에게 큰 수정을 시키기 전에 먼저 커밋**해 둔다. 그러면 언제든 돌아올 수 있다.

### 항상 이 순서
`status`(뭐가 바뀌었나 보고) → `add .`(올리고) → `commit -m`(저장) → `log`(잘 됐나 확인)

### 직접 해보기
저장소 폴더(`claude-test`)에서:
```
git status
git add .
git commit -m "선생님 웹 UI 1차: 목업 데이터로 화면 구성"
git log --oneline
```
- [ ] `git status`에서 `Agent.md`, `개발기획서.md`, `docs/`, `app/`이 빨갛게 보였다
- [ ] 커밋 후 `git log --oneline`에 내 메시지가 맨 위에 있다
- [ ] 다시 `git status`를 치면 "nothing to commit, working tree clean"이 나온다 (=전부 저장됨)

## 3. 프로젝트 폴더 지도

### 왜 알아야 하나
AI에게 "공지 화면 글자 바꿔줘"라고 하면 AI는 찾아서 한다. 하지만 **내가 어디에 뭐가 있는지 알면** 요청이 정확해지고, AI가 이상한 곳을 고쳤을 때 눈치챌 수 있다.

### 지도

```
claude-test/                 ← 저장소 (Git이 관리하는 범위)
├── Agent.md                 ← AI에게 먼저 읽게 하는 프로젝트 상황판
├── 개발기획서.md              ← 무엇을 만들지 (기능, 일정, 데이터 설계)
├── docs/                    ← 학습 자료, 결정 기록
└── app/                     ← ★ Flutter 앱 (진짜 코드는 전부 여기)
    ├── pubspec.yaml         ← 이 앱이 쓰는 라이브러리(부품) 목록. 앱 이름도 여기
    ├── lib/                 ← ★★ 내가 볼 코드는 전부 여기
    │   ├── main.dart        ← 시작점. 앱을 켜면 이 파일부터 실행된다
    │   ├── models/          ← 데이터 모양 (학생, 벌점, 공지가 어떤 칸을 가지는지)
    │   ├── services/        ← 데이터를 가져오고 저장하는 코드 (지금은 가짜 데이터, 3주차에 Firebase로)
    │   ├── screens/         ← 화면
    │   │   ├── login_screen.dart
    │   │   ├── teacher/     ← 선생님 화면들 (대시보드, 벌점, 도시락, ...)
    │   │   └── student/     ← 학생 화면들 (나중에)
    │   └── widgets/         ← 여러 화면에서 같이 쓰는 UI 부품
    ├── web/                 ← 웹으로 실행할 때 필요한 껍데기. 건드릴 일 거의 없음
    ├── android/             ← Android용 껍데기. 나중에
    ├── test/                ← 자동 테스트. 지금은 신경 안 씀
    └── build/               ← 컴퓨터가 자동 생성하는 결과물. 열어볼 필요 없음, Git에도 안 올라감
```

### 규칙
- **화면 하나 = 파일 하나.** "벌점 화면" 문제면 `lib/screens/teacher/` 안의 벌점 파일이다.
- 파일 맨 위에 한국어 설명 주석이 있다. 파일을 열면 **첫 3줄**을 읽는다.
- `build/`, `.dart_tool/`은 무시한다. 자동 생성물이다.

### 직접 해보기
VS Code에서 `app` 폴더를 열고(`파일 > 폴더 열기`):
- [ ] `lib/main.dart`를 열어 첫 주석을 읽었다
- [ ] `lib/screens/teacher/` 안에 어떤 파일들이 있는지 이름을 훑었다
- [ ] `Ctrl + Shift + F`(전체 검색)로 `대시보드`를 검색해서 어느 파일에 있는지 찾았다

## 4. 앱 실행과 확인

### 원칙
**"만들었다"와 "돌아간다"는 다르다.** AI가 "완료했습니다"라고 하면 반드시 내가 실행해서 눈으로 본다.

### 실행

```
cd C:\Users\khgg0\orca\claude-test\app
flutter run -d chrome
```
- `-d chrome`은 "Chrome에서 실행"이라는 뜻이다. (`-d`는 device, 어디서 돌릴지)
- 처음엔 30초~1분 걸린다. Chrome이 저절로 열리며 앱이 뜬다.
- 터미널에 `Flutter run key commands` 라는 안내가 나오면 준비 끝이다.

### 실행 중 키 (터미널 창을 클릭한 뒤 누른다)

| 키 | 뜻 |
|----|-----|
| `r` | **핫 리로드.** 코드를 바꾼 뒤 누르면 1~2초 안에 화면에 반영. 가장 많이 쓴다 |
| `R` | 앱을 처음부터 다시 시작. `r`로 반영이 안 될 때 |
| `q` | 앱 종료 |

### 오류가 나는 곳 두 군데
1. **터미널의 빨간 글자** — 코드가 잘못돼 실행조차 안 될 때. `Error:` 뒤와 `lib/...dart:줄번호` 부분이 핵심이다.
2. **브라우저의 빨간 화면** — 실행은 됐는데 특정 화면에서 터질 때. 화면에 적힌 영어 문장을 복사한다.

### 직접 해보기
1. 위 명령으로 앱을 실행하고 "선생님으로 체험"으로 들어간다.
2. VS Code에서 `Ctrl + Shift + F`로 `대시보드`를 검색해 화면 제목이 있는 파일을 연다.
3. 글자를 `대시보드`에서 `대시보드 (수정 테스트)`로 바꾸고 저장(`Ctrl + S`).
4. 터미널을 클릭하고 `r`을 누른다.
- [ ] Chrome 화면의 글자가 바뀌었다
- [ ] 다시 원래대로 고치고 `r`을 눌러 되돌렸다
- [ ] `q`로 종료했다

## 5. AI에게 말하는 법

### 바이브 코딩의 핵심 규칙 5개

**① 한 번에 하나만**
- ❌ "도시락 기능 만들어줘"
- ✅ "도시락 관리 화면에서 날짜별 신청자 수를 메뉴별로 나눠서 보여줘"

크게 요청하면 크게 망가지고, 어디가 잘못됐는지 찾기도 어렵다.

**② 시작 전에 커밋**
AI에게 수정을 시키기 전에 `git add .` → `git commit`. 망가지면 `git restore .`로 돌아온다.

**③ 오류는 그대로 복사해서 붙인다**
- ❌ "빨간 오류 나요"
- ✅ 아래 형식으로:
```
[무엇을 하다가] 벌점 부여 화면에서 점수 없이 저장 버튼을 누르니
[어디에] 브라우저에 빨간 화면
[오류 내용]
(빨간 글자 그대로 붙이기)
```

**④ "어떻게 확인하나요?"를 항상 묻는다**
AI가 코드를 쓰면 "이게 됐는지 내가 어떻게 확인해요?"를 묻고, **그 확인을 내가 직접 한다.**

**⑤ "됐습니다"는 실행해 본 뒤에만 믿는다**
AI는 자기 코드를 실행해 보지 않고 "완료"라고 말할 수 있다. 실행 결과를 본 사람은 나만이다.

### 좋은 요청 문장 틀
> `[파일 또는 화면]`에서 `[지금 상태]`인데 `[원하는 상태]`로 바꿔줘. 바꾼 뒤 어떻게 확인하는지도 알려줘.

예: "`학생 목록` 화면에서 지금은 이름으로만 검색되는데 좌석번호로도 검색되게 바꿔줘. 바꾼 뒤 어떻게 확인하는지도 알려줘."

### 세션 시작 시 첫 문장
> "Agent.md 먼저 읽고 시작해. 오늘은 `[기능 하나]`만 할 거야."

### 직접 해보기
- [ ] 앱을 보고 고치고 싶은 것 하나를 위 "요청 문장 틀"로 적어 봤다 (아직 요청은 안 해도 된다)
- [ ] 그 전에 커밋을 했다 (2번 항목)
