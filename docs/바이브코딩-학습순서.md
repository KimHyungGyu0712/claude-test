# 바이브 코딩으로 이 서비스를 만들 때 내가 알아야 할 것 (우선순위 순)

- **작성일:** 2026-09-05
- **전제:** 코드는 AI(Claude Code 등)가 쓴다. 나는 **방향을 정하고, 실행해서 확인하고, 문제를 설명하는 사람**이다.
- **원칙:** 문법을 외우지 않는다. AI가 쓴 코드를 **읽고 어디가 무엇인지 알아보는 수준**이면 충분하다. 대신 "실행·확인·되돌리기"는 반드시 내가 할 줄 알아야 한다.

---

## 0단계. 지금 당장 (1주차 전반, 환경 세팅과 함께)

AI가 대신 못 해주는 것들이다. 이걸 모르면 AI가 코드를 써도 내가 돌려볼 수 없다.

| # | 알아야 할 것 | 어느 정도까지 | 왜 필요한가 |
|---|------------|-------------|-----------|
| 1 | **터미널(PowerShell) 기본** | 폴더 이동(`cd`), 명령 실행, 출력 읽기. 그리고 `flutter doctor`, `flutter run` 두 개 | AI는 코드를 쓰지만 실행 버튼은 내가 누른다. 오류 메시지도 여기서 나온다 |
| 2 | **Git 5개 명령** | `git status`, `git add .`, `git commit -m "메시지"`, `git log`, `git checkout -- .`(되돌리기) | AI가 코드를 망가뜨렸을 때 **직전 상태로 돌아가는 안전벨트**. 기능 하나 완성될 때마다 커밋 |
| 3 | **프로젝트 폴더 지도** | `lib/main.dart`가 시작점, `lib/screens/`가 화면, `lib/services/`가 Firebase 통신, `pubspec.yaml`이 라이브러리 목록 | AI에게 "학생 공지 화면 고쳐줘"라고 할 때 어느 파일인지 내가 알아야 대화가 빠르다 |
| 4 | **앱 실행과 확인 방법** | Chrome에서 실행, 에뮬레이터에서 실행, 핫 리로드(`r`), 콘솔에서 빨간 오류 찾기 | "만들었다"와 "돌아간다"는 다르다. 매번 내가 직접 실행해서 확인한다 |
| 5 | **AI에게 말하는 법** | 한 번에 기능 하나만, 오류 메시지는 **그대로 복사해서** 붙이기, 항상 "어떻게 확인하나요?" 묻기, "됐다"는 말은 실행해 본 뒤에만 믿기 | 바이브 코딩의 성패는 여기서 갈린다. 크게 요청하면 크게 망가진다 |

**완료 기준:** 기본 Flutter 앱을 Chrome과 에뮬레이터에서 실행하고, 글자 하나 바꿔서 핫 리로드로 반영되는 것을 보고, 커밋 한 번 한다.

## 1단계. 읽을 줄 알아야 하는 개념 (1~2주차)

쓰는 게 아니라 **읽는** 목표다. AI가 쓴 코드를 보고 "아, 이게 화면이고 이게 버튼이구나"를 알아보면 된다.

| # | 알아야 할 것 | 어느 정도까지 | 왜 필요한가 |
|---|------------|-------------|-----------|
| 6 | **Dart 읽기** | 변수, 함수, `if`, 리스트(목록), 클래스(데이터 묶음)가 코드에서 어떻게 생겼는지 알아보기 | 코드를 읽어야 AI가 이상한 걸 만들었는지 눈치챈다 |
| 7 | **Flutter의 그림** | 화면은 **위젯**(부품)을 겹겹이 쌓은 것. 값이 바뀌면 다시 그려진다(`setState`). 화면 이동은 `Navigator` | "이 버튼 누르면 저 화면으로" 같은 요청을 정확한 말로 할 수 있다 |
| 8 | **앱과 서버의 관계** | 앱(내 폰)은 화면만, 데이터는 Firebase(서버)에 있다. 로그인은 Authentication, 데이터는 Firestore, 알림은 FCM | 이걸 모르면 "왜 다른 폰에서는 안 보이지?" 같은 질문을 계속 하게 된다 |
| 9 | **Firestore 구조** | 컬렉션(시트) → 문서(행) → 필드(칸). 기획서 5번의 표가 그대로 이것이다 | Firebase 콘솔에서 데이터가 제대로 들어갔는지 **내 눈으로 확인**해야 한다 |
| 10 | **기다림(비동기)** | 서버에서 데이터를 가져오는 데 시간이 걸린다. 그동안 로딩 표시를 보여준다(`Future`, `async/await`) | 초보자가 만나는 버그의 절반은 여기서 나온다. 개념만 알면 AI 설명이 이해된다 |

**완료 기준:** AI가 만든 연습용 화면 3개의 코드를 열어서, 어디가 화면 이동이고 어디가 데이터 목록인지 손으로 짚을 수 있다.

## 2단계. AI가 못 대신하는 내 몫 (3주차부터, 기능 개발과 병행)

계정, 콘솔 클릭, 실제 기기 테스트, 보안 확인은 **내 손과 내 판단**이 들어가야 한다.

| # | 알아야 할 것 | 어느 정도까지 | 왜 필요한가 |
|---|------------|-------------|-----------|
| 11 | **Firebase 콘솔 사용** | 프로젝트 만들기, Authentication·Firestore 켜기, 데이터 직접 보기·고치기, 사용량 확인 | AI는 콘솔 버튼을 못 누른다. 로그인이 안 될 때 콘솔에서 계정이 있는지 보는 건 내 일 |
| 12 | **보안 규칙 확인** | "학생은 자기 것만, 선생님은 전체"가 실제로 막히는지 **직접 테스트** | 미성년자 정보다. AI가 규칙을 써도 **막히는지 확인하는 책임은 나**에게 있다 |
| 13 | **비밀 파일 관리** | `google-services.json`, API 키 같은 건 Git에 올리지 않는다(`.gitignore`) | 실수로 GitHub에 올리면 남이 내 Firebase를 쓸 수 있다 |
| 14 | **실제 폰에서 테스트** | Android 개발자 모드, USB 디버깅, APK 설치 | 에뮬레이터에서 되고 실제 폰에서 안 되는 일은 흔하다. 학원 배포 전 필수 |
| 15 | **디버깅 루프** | 오류 읽기 → 언제 생기는지 재현 → AI에게 상황과 오류를 함께 전달 → 고친 뒤 **다시 실행해 확인** | "고쳤습니다"를 그대로 믿지 않는다. 증거(실행 결과)를 보고 넘어간다 |

**완료 기준:** 학생 계정으로 로그인해서 다른 학생 벌점을 보려 했을 때 실제로 막히는 것을 확인했다.

## 지금은 배우지 않아도 되는 것

시간을 아끼기 위해 **의도적으로 미룬다.** 필요해지면 그때 AI에게 물으면 된다.

- Dart 고급 문법 (제네릭, 믹스인, 확장 함수 등)
- 상태 관리 라이브러리 (Riverpod, Bloc, Provider 등) — 이 규모에서는 `setState`로 충분
- 서버 직접 구축 (Node.js, 데이터베이스 설계 이론) — Firebase가 대신한다
- 자동 배포(CI/CD), 테스트 코드 작성
- iOS 빌드 — Mac이 생긴 뒤
- 디자인 이론 — 기획서의 UI 시안을 AI에게 보여주고 따라 만들게 한다

## 바이브 코딩 세션 시작 전 체크 (매번)

1. `Agent.md`를 AI에게 먼저 읽게 한다.
2. 오늘 만들 기능은 **하나**만 정한다. (예: "선생님이 공지 등록" — "공지 기능 전체"가 아니다)
3. 만들기 전에 커밋해 둔다. (되돌아올 지점)
4. AI가 "완료"라고 하면 **내가 실행해서** 확인한다.
5. 확인되면 커밋하고, `Agent.md` 9번 결정 기록이나 막힌 문제를 적는다.
