# 학생용 모바일 버전 개발 기획서

- **작성일:** 2026-09-05
- **대상 독자:** 이 프로젝트를 구현할 개발자(AI 에이전트 포함)
- **전제:** 개발 장비는 **Windows PC만** 있다. Mac은 없다. 선생님용 웹은 `app/`에 1차 구현되어 있고, 학생용은 `lib/screens/student/`에 자리표시 화면 하나만 있다.
- **상위 문서:** `개발기획서.md`(기능 명세·데이터 설계), `Agent.md`(규칙·결정 기록)

## 1. 결론 먼저 — 웹인가, 앱인가

**하나의 Flutter 코드로 다음 세 가지를 동시에 낸다.**

| 대상 | 형태 | 이유 |
|------|------|------|
| **Android 학생** | **앱 (APK → Google Play)** | Windows에서 바로 빌드된다. 푸시 알림이 가장 확실하다. |
| **iPhone 학생** | **1차: 웹앱 (PWA, 홈 화면에 추가)** | Windows에서는 iOS 앱을 빌드할 수 없다. 웹은 빌드 없이 Safari로 바로 쓴다. |
| **iPhone 학생** | **2차: 앱 (App Store), 앱이 안정된 뒤** | 클라우드 Mac(Codemagic 등)으로 빌드. 푸시 알림 신뢰성이 필요해질 때 진행. |

한 줄로: **Android는 앱, iPhone은 우선 웹, 코드는 하나.** 선생님용 웹과 같은 프로젝트에서 역할에 따라 화면만 갈라진다.

### 판단 근거

| 기준 | 웹앱 (PWA) | 네이티브 앱 |
|------|-----------|------------|
| Windows에서 빌드 | 가능 | Android 가능 / **iOS 불가 (Mac 필수)** |
| iPhone에서 쓰기 | Safari에서 주소 열고 "홈 화면에 추가" | 클라우드 Mac 빌드 + Apple 개발자 등록($99/년) + 심사 |
| 푸시 알림 | Android Chrome 가능 / iOS는 **홈 화면에 추가한 경우만**, iOS 16.4 이상, 신뢰성 낮음 | 확실 (FCM) |
| 배포·업데이트 | 서버에 올리면 즉시 반영, 심사 없음 | 스토어 심사(Apple 1~3일), 사용자가 업데이트해야 반영 |
| 설치 부담 | 주소 안내 + 홈 화면 추가 2단계 | 스토어에서 설치 |
| 카메라 (QR 스캔) | 브라우저 카메라 API로 가능 (선생님 쪽 기능) | 가능 |
| 내 QR 표시 | 그냥 이미지. 문제 없음 | 문제 없음 |
| 오프라인 | 필요 없음 (학원은 Wi-Fi) | — |
| 비용 | Firebase Hosting 무료 | Play $25(1회), Apple $99/년, 클라우드 Mac 빌드 무료 한도 있음 |

**결정적인 사실 두 가지**

1. **학생 기능 중 네이티브가 꼭 필요한 것은 푸시 알림 하나뿐이다.** 도시락 신청, 질문, 민원, 공지, 벌점 조회, 내 QR 표시는 전부 웹으로 동일하게 된다.
2. **iOS 앱은 Windows에서 절대 빌드되지 않는다.** 클라우드 Mac을 쓰면 되지만, 입문자가 첫 3개월에 Apple 계정·인증서·프로비저닝·심사까지 감당하는 것은 일정상 무리다. 그래서 iPhone은 웹으로 먼저 실사용에 들어가고, 앱은 2차로 미룬다.

### 순수 웹만 하지 않는 이유
Android는 Windows에서 30초면 APK가 나온다. 앱으로 내면 푸시 알림이 확실하고, 학생이 홈 화면에 아이콘을 두고 쓰는 경험이 자연스럽다. 비용이 거의 없으니 Android만은 앱으로 간다.

### 순수 앱만 하지 않는 이유
iPhone 학생을 3개월 동안 아예 못 쓰게 두는 것보다, 웹으로라도 첫날부터 쓰게 하는 것이 낫다. 코드가 같으므로 웹을 낸다고 앱 개발이 늦어지지 않는다.

## 2. 목표와 범위

### 목표
학생이 **자리에서 폰으로** 도시락 신청, 질문 접수, 민원 신고, 공지 확인, 벌점 조회, 내 QR 표시를 한다.
선생님이 웹에서 처리하면 학생 폰에 **실시간으로** 반영된다.

### 이번 범위 (3개월 내)
- 학생용 모바일 화면 (아래 4번)
- Android APK 빌드와 학원 내 직접 배포, 이후 Google Play 등록
- iPhone용 PWA (Firebase Hosting, 홈 화면 추가 안내 화면 포함)
- 푸시 알림: Android 앱 필수, iOS PWA는 되면 좋고 안 되면 앱 내 알림 목록으로 대체

### 이번 범위 밖 (2차)
- iOS 네이티브 앱 (App Store)
- 오프라인 동작
- 생체 인증, 위젯 등 네이티브 전용 기능

## 3. 아키텍처 — 한 프로젝트, 역할별 화면

```
로그인 → 역할 확인
   ├─ teacher/admin → TeacherShell (사이드바, 넓은 화면)     ← 이미 있음
   └─ student       → StudentShell (하단 탭, 세로 화면)      ← 이번에 만든다
```

- **프로젝트를 나누지 않는다.** `app/` 하나에서 학생 화면을 추가한다. 모델(`lib/models/`)과 데이터 서비스(`lib/services/`)는 선생님용과 **공유**한다. 선생님이 벌점을 넣는 함수와 학생이 벌점을 읽는 함수가 같은 서비스에 있다.
- **화면 크기로 갈라지지 않고 역할로 갈라진다.** 선생님이 폰 브라우저로 열어도 선생님 화면(순찰용)이 나와야 하기 때문. 단, 선생님 화면은 폰 폭에서도 깨지지 않게 최소한의 반응형 처리를 한다(2차).
- **빌드 대상**
  - `flutter build apk --release` → Android 앱
  - `flutter build web --release` → 선생님 웹 + iPhone 학생 PWA (같은 산출물, Firebase Hosting에 배포)

### 폴더 구조 (추가분)

```
app/lib/
├── screens/
│   └── student/
│       ├── student_shell.dart          ← 하단 탭 틀 (홈/도시락/요청/내 정보)
│       ├── student_home_screen.dart    ← 공지 + 오늘 요약
│       ├── notice_list_screen.dart     ← 공지 목록
│       ├── notice_detail_screen.dart   ← 공지 상세
│       ├── penalty_history_screen.dart ← 내 벌점
│       ├── lunch_order_screen.dart     ← 도시락 신청/취소
│       ├── question_screen.dart        ← 질문 접수 + 내 질문 상태
│       ├── complaint_screen.dart       ← 민원 신고 + 내 민원 상태
│       ├── my_qr_screen.dart           ← 내 QR 코드
│       └── install_guide_screen.dart   ← iPhone "홈 화면에 추가" 안내
├── widgets/
│   └── mobile/                          ← 모바일 전용 부품 (공용 widgets 재사용 우선)
└── services/
    └── notification_service.dart       ← FCM 토큰 등록, 알림 수신 (3주차 Firebase 연결 이후)
```

## 4. 화면 명세 (학생)

모바일 기본 규칙: **세로 화면, 한 손 조작, 하단 탭 4개, 각 화면은 한 가지 일만.**

### 4.0 하단 탭
| 탭 | 내용 |
|----|------|
| 홈 | 공지 최신 3건, 오늘 도시락 신청 상태, 내 벌점 합계, 대기 중 질문/민원 수 |
| 도시락 | 이번 주 날짜별 메뉴, 신청/취소 |
| 요청 | 질문 접수 / 민원 신고 (상단 탭으로 전환) |
| 내 정보 | 이름·좌석, 내 QR, 벌점 내역, 비밀번호 변경, 로그아웃 |

### 4.1 로그인 (공용, 이미 있음 → 수정)
- 폰 폭에서 카드가 화면 폭에 맞게 늘어난다.
- 역할이 student면 `StudentShell`로 이동. "학생으로 체험" 버튼은 Firebase 연결 후 제거.
- 최초 로그인 시 비밀번호 변경 화면으로 유도 (기획서 4.1).

### 4.2 홈
- 상단: "OO 학생, 좌석 N번" 인사.
- 카드 1: 최신 공지 3건. 중요 공지는 빨간 표시. 탭하면 상세.
- 카드 2: 오늘 도시락. "신청함: 제육덮밥" / "미신청 (마감 10:30)" / "마감됨".
- 카드 3: 내 벌점 합계 + 최근 1건.
- 카드 4: 대기 중 질문 n건, 처리 중 민원 n건.

### 4.3 공지
- 목록: 최신순, 중요 공지 상단 고정, 제목·날짜·첫 줄 미리보기.
- 상세: 제목, 작성자, 날짜, 전문.
- 새 공지 도착 시 푸시 알림 (Android 앱 필수).

### 4.4 도시락 신청
- 이번 주 월~금 날짜 칩. 오늘이 기본 선택.
- 날짜별: 메뉴 목록(라디오 선택), 마감 시간, 현재 상태.
- 버튼: 미신청이면 "신청", 신청했으면 "취소" (마감 전까지만).
- 마감 후: 버튼 비활성 + "마감되었습니다" 표시.
- 규칙: 하루 1건, 마감 시각은 서버(Firestore) 기준으로 판정.

### 4.5 질문 접수
- 입력: 과목(선택), 내용(여러 줄), 접수 버튼.
- 아래: 내 질문 목록. 상태 칩(대기/배정/완료). 배정되면 "N시 OO 선생님" 표시.
- 배정 시 푸시 알림.

### 4.6 민원 신고
- 입력: 내용(여러 줄), 접수 버튼.
- 아래: 내 민원 목록. 상태 칩(접수/처리중/완료). 완료 시 답변 표시.
- 상태 변경 시 푸시 알림.

### 4.7 내 정보
- 이름, 좌석번호, 계정 이메일.
- **내 QR 코드**: 학생 uid를 담은 QR. 흰 배경에 크게. 선생님이 순찰 때 스캔.
- 벌점 내역: 날짜, 사유, 점수, 합계.
- 비밀번호 변경, 로그아웃.
- iPhone 웹에서 열었을 때만: "홈 화면에 추가하기" 안내 배너 (4.8).

### 4.8 설치 안내 (iPhone 웹 전용)
- Safari에서 처음 접속하면 하단에 안내: "공유 버튼 → 홈 화면에 추가". 그림 3장.
- 홈 화면에서 실행 중(standalone)이면 표시하지 않는다.
- 알림을 받으려면 홈 화면 추가가 필수라는 점을 알린다.

## 5. 기술 항목

### 5.1 반응형 기준
- 폭 600px 미만 = 모바일 레이아웃. `MediaQuery`로 판정하는 공용 헬퍼 하나(`isMobile(context)`).
- 학생 화면은 모바일 레이아웃만 지원한다(태블릿은 그냥 늘어남).

### 5.2 PWA 설정 (`app/web/`)
- `manifest.json`: 앱 이름, 아이콘(192/512), `display: standalone`, 테마색, 시작 URL.
- `index.html`: iOS용 메타 태그(`apple-mobile-web-app-capable`, 아이콘, 상태바 색).
- Flutter가 기본 생성한 service worker 사용. 커스텀 캐싱은 하지 않는다.

### 5.3 푸시 알림 (3주차 Firebase 연결 후)
| 플랫폼 | 방법 | 기대 수준 |
|--------|------|----------|
| Android 앱 | FCM, `firebase_messaging` | 필수. 백그라운드·종료 상태 모두 수신 |
| Android Chrome(웹) | FCM 웹 푸시 | 되면 좋음 |
| iOS PWA | 웹 푸시 (iOS 16.4+, 홈 화면 추가 필수) | 되면 좋음. 안 되는 기기는 **앱 내 알림 목록**으로 대체 |
| iOS 앱 (2차) | FCM + APNs | 필수 (2차) |

- 알림 발송은 선생님 웹에서 직접 하지 않고 **Cloud Functions**가 Firestore 변경(공지 생성, 질문 배정, 민원 상태 변경)을 감지해 보낸다. 클라이언트에 서버 키를 두지 않기 위함.
- 앱 내 알림 목록(`notifications` 컬렉션)을 두어 푸시가 안 오는 환경에서도 홈 탭에서 확인 가능하게 한다.

### 5.4 QR
- 학생 QR 내용: `hagwon:student:<uid>` 형식의 문자열.
- 생성: `qr_flutter` 패키지 (순수 Dart, 웹·Android 모두 동작). **추가 패키지 1개.**
- 스캔(선생님 웹, 11주차): `mobile_scanner` 패키지. 브라우저 카메라 권한 필요. HTTPS에서만 동작하므로 Firebase Hosting 배포 후 테스트.

### 5.5 Android 빌드·배포
- 1차: `flutter build apk --release`로 APK 파일을 만들어 학원 내에서 직접 설치(출처 불명 앱 허용 안내 필요).
- 2차: Google Play Console 등록($25). `flutter build appbundle`. 미성년자 대상이므로 **가족 정책·데이터 안전 섹션** 작성 필수.
- 서명 키(`key.properties`, `*.jks`)는 Git에 올리지 않는다. `.gitignore`에 추가.

### 5.6 iOS 경로 (2차)
- Windows에서는 `ios/` 폴더 파일 생성만 가능하고 빌드는 불가.
- 클라우드 빌드: **Codemagic**(Flutter 공식 파트너, 무료 한도 있음) 또는 GitHub Actions macOS 러너.
- 필요 항목: Apple 개발자 계정($99/년), 인증서·프로비저닝(Codemagic이 자동 관리 가능), TestFlight로 학원 내 테스트 → App Store 심사.
- 실기기 테스트: 학원 내 iPhone에 TestFlight 설치.
- **착수 조건:** Android 앱과 PWA가 실제 학원에서 2주 이상 문제없이 쓰인 뒤.

### 5.7 보안·개인정보 (미성년자)
- 학생은 Firestore에서 **자기 uid 문서만** 읽고, 자기 도시락·질문·민원만 쓴다. Security Rules로 강제. 다른 학생 QR을 만들어 낼 수 없다(uid는 로그인으로만 알 수 있음).
- 앱에 저장하는 것: 로그인 토큰만. 이름·연락처는 서버에서 읽는다.
- 개인정보 처리방침 페이지를 Firebase Hosting에 게시(스토어 등록 필수).

### 5.8 추가 패키지 (이유 포함)
| 패키지 | 용도 | 시점 |
|--------|------|------|
| `firebase_core`, `firebase_auth`, `cloud_firestore` | 로그인·DB | 3주차 |
| `firebase_messaging` | 푸시 | 10주차 |
| `qr_flutter` | 내 QR 표시 | 10주차 |
| `mobile_scanner` | 선생님 QR 스캔 | 11주차 |

이 외 상태 관리·라우팅 패키지는 추가하지 않는다 (`setState` + `ChangeNotifier` 유지).

## 6. 일정 (기존 12주 일정에 끼워 넣기)

학생 화면은 선생님 기능과 **같은 주에 짝으로** 만든다. 데이터 서비스가 공유되므로 추가 비용이 작다.

| 주차 | 선생님 (기존) | 학생 모바일 (추가) | 완료 기준 |
|------|-------------|------------------|----------|
| 2 | — | `StudentShell` 하단 탭 틀, 홈 화면 뼈대 (mock) | Chrome 모바일 보기(F12 → 폰 모양)에서 탭 전환 |

## 8. 위험과 대응

| 위험 | 대응 |
|------|------|
| iOS PWA 푸시가 안 오는 기기가 있다 | 앱 내 알림 목록으로 대체. 중요 공지는 학원에서 구두 병행. 2차에 iOS 앱 |
| iPhone 학생이 "홈 화면에 추가"를 안 한다 | 설치 안내 화면 + 학원 등록 시 선생님이 직접 도와 추가 |
| APK 직접 설치를 어려워한다 | 설치 안내문 1장 배포. 2차에 Google Play 등록 |
| Flutter 웹 첫 로딩이 느리다 | 학원 Wi-Fi 기준 허용 범위. 로딩 화면에 학원 로고 표시. 2차에 최적화 |
| 선생님 화면이 폰에서 깨진다 | 순찰은 태블릿 권장. 폰 대응은 2차 |

## 9. 결정 요약

1. **Android = 앱, iPhone = 1차 웹(PWA) → 2차 앱.** 코드는 하나.
2. 학생 화면은 `lib/screens/student/`에 하단 탭 구조로 추가. 선생님 화면과 모델·서비스 공유.
3. 푸시는 Cloud Functions에서 발송. 웹 푸시가 안 되는 환경은 앱 내 알림 목록으로 보완.
4. 추가 패키지는 Firebase 4종 + `qr_flutter` + `mobile_scanner`로 제한.
5. iOS 앱 착수 조건: Android 앱·PWA가 학원에서 2주 이상 안정 사용.
